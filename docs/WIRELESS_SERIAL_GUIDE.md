# 无线串口透传接入

适用于 Zigbee（CC2530 等）、LoRa、蓝牙透传、nRF 系列等**串口透传模块**。

## 结论：按普通串口接入即可

透传模块对电脑而言就是一个 COM 口，无线那一段对本软件完全透明。软件不需要知道底下是有线还是无线。

```
主控板 UART ── 无线模块 ))) 2.4G / 433M ((( 无线模块 ── USB 转串口 ── 电脑 COM 口
                                                                        ↑
                                                                  软件从这里接入
```

**操作**：串口工作台 → 右侧检查器「数据源」选**本地串口** → 选中 COM 口 → 设置波特率 → 连接。

> **不要选 TCP 或 UDP。** 那两项是给 ser2net、ESP-Link 这类"串口转网络"桥接设备用的（设备在局域网里暴露一个 IP 和端口）。无线透传模块的末端是 COM 口，走的是本地串口这条路。

## 波特率对的是模块，不是远端设备

无线链路上其实有两段独立的 UART：

| 段            | 谁和谁                | 在哪里配置       |
| ------------- | --------------------- | ---------------- |
| 电脑侧        | 电脑 ↔ 本地无线模块   | 本软件的波特率   |
| 设备侧        | 远端无线模块 ↔ 主控板 | 主控板固件       |

本软件设置的是**电脑侧**这一段。两段速率不一致时不会报错，但模块内部缓冲会溢出并**静默丢数据**。建议两段配成相同速率。

## 三个常见问题

### 1. 数据缺一块、断断续续

**最常见的原因是无线吞吐跟不上 UART 速率。**

空口速率是理论峰值，透传模块的实际有效吞吐远低于它。例如 802.15.4 空口标称 250 kbps，透传模块实测通常只有 20–60 kbps。如果 UART 设成 115200 且持续满速发送，模块缓冲很快溢出。

这种丢失发生在**模块内部**，软件端无法区分"设备没发"和"无线丢了"。

处理办法，按顺序尝试：

1. 降低设备的发送频率（最有效）
2. 降低两端 UART 波特率
3. 缩短单帧长度
4. 确认无线信道没有被 Wi-Fi 干扰（2.4G 尤其明显）

### 2. 一行数据被切成好几段

无线是按帧收发的，还有重传，因此数据**成批到达**而非均匀流入，一行文本很可能被切在两个无线帧里。

软件的分帧层持有跨分片残留状态，被切断的行会正确拼回，正常情况下无需额外配置。如果仍看到断行，检查「更多 → 接收分帧」的模式是否与数据格式匹配（见下节）。

### 3. 波形横轴看起来在抖或来回跳

这是无线到达抖动的正常表现，软件已做处理：

- 波形横轴使用**采样序号 ÷ 采样率**而非主机接收时间戳。成批到达时若按接收时间定位，横轴会来回折返
- 采样率估算带平滑，抵消到达间隔抖动

因此波形本身不会因为无线抖动而变形。若横轴时间刻度与实际不符，在图表配置里手动指定采样率即可。

## 接收分帧模式怎么选

位置：串口工作台 → 更多 → 接收分帧

| 数据形态                         | 选择         | 说明                                                     |
| -------------------------------- | ------------ | -------------------------------------------------------- |
| 带换行（`printf` 那类）          | 自动         | 默认值，按 LF 断行并自动去掉行尾 CR                      |
| 无换行、定长包或纯二进制         | 超时分帧     | 静默指定毫秒数后认为一帧结束                             |
| 有固定包头包尾                   | 自定义分隔符 | 支持文本或 HEX 输入（如 `0D 0A`）                        |

> **无线链路请调大超时分帧的空闲时间。** 默认 50 ms 是按有线串口设定的；无线帧间隔本身就可能超过 50 ms，设得太小会把一包数据切成好几段。建议从 100–200 ms 起调。

## 传二进制协议前先确认透传是否真的"全透明"

若要传 JustFloat 等二进制格式，先确认无线模块固件是**完全字节透传**的。

部分透传固件保留了 AT 命令触发序列（典型是 `+++`）。当二进制数据中恰好出现该序列时，模块会切入命令模式，导致数据损坏，且现象随机、很难排查。

判断方法：查模块手册是否有"命令模式触发字符"或"逃逸序列"，能关闭就关闭。纯文本协议（JSON、KV、CSV）不受此影响。

## 与其他数据源的关系

无线透传接入后与普通串口**完全等价**，串口工作台的全部能力都可用：

- 日志视图、终端视图、文本/HEX 收发
- 图表解析（JSON、KV、分隔符、正则、JustFloat）
- 数据滤波、FFT、XY 散点、IMU 姿态
- 控制面板组件、AI 数据桥接
- 导出 TXT / CSV / PNG
